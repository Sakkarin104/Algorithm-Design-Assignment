# ข้อ 1 การกลับลำดับสตริง (String Reversal)

### 1. คำอธิบายแนวคิดของอัลกอริทึมแต่ละวิธี
* **อัลกอริทึมที่ 1 (Recursive Algorithm):** อาศัยหลักการแบ่งปัญหาให้เล็กลง โดยนำตัวอักษรตัวสุดท้ายของสตริงปัจจุบัน มาต่อเข้ากับผลลัพธ์ของการเรียกซ้ำ (Recursive call) ที่ส่งค่าสตริงส่วนที่เหลือ (ตัดตัวสุดท้ายออกไปแล้ว) เข้าไปทำงาน ทำซ้ำไปเรื่อยๆ จนกว่าสตริงจะว่างเปล่า
  * **Base Case (กรณีฐาน):** `if (s == null || s.isEmpty())` หยุดการเวียนเกิดและคืนค่าเดิมกลับไปเมื่อสตริงว่างเปล่า
  * **Recursive Case (กรณีเวียนเกิด):** `return lastChar + reverseRecursive(remainingString);` ตัดตัวอักษรสุดท้ายออก แล้วเรียกตัวเองซ้ำด้วยสตริงที่สั้นลง
* **อัลกอริทึมที่ 2 (Iterative Algorithm):** ใช้ลูป (Loop) ถอยหลัง เริ่มอ่านข้อความจากตำแหน่งดัชนี (Index) สุดท้ายของสตริง แล้วลดค่าดัชนีลงทีละ 1 เพื่อถอยหลังกลับไปยังตำแหน่งแรกสุด จากนั้นนำตัวอักษรที่อ่านได้ในแต่ละรอบมาต่อกันเป็นสตริงใหม่

### 2. Pseudocode หรือผังขั้นตอนการทำงาน
**Algorithm 1: Recursive**
```text
FUNCTION reverseRecursive(s)
    IF s is empty OR s is null THEN
        RETURN s
    END IF
    last_char = GET LAST CHARACTER OF s
    remaining = REMOVE LAST CHARACTER FROM s
    RETURN last_char + reverseRecursive(remaining)
END FUNCTION
```

**Algorithm 2: Iterative**
```text
FUNCTION reverseIterative(s)
    IF s is empty OR s is null THEN
        RETURN s
    END IF
    result = ""
    FOR i = LENGTH(s) - 1 DOWN TO 0 DO
        result = result + s[i]
    END FOR
    RETURN result
END FUNCTION
```

### 3. โปรแกรมภาษา Java ที่สามารถทำงานได้จริง
* โค้ดโปรแกรมฉบับสมบูรณ์ถูกจัดเก็บไว้ในไฟล์ `StringReversal.java` ภายในโฟลเดอร์นี้ ซึ่งมีการแยกเมธอดชัดเจนและจัดการกรณีข้อมูลว่างเปล่า (Empty/Null) เรียบร้อยแล้ว

### 4. ตัวอย่างข้อมูลนำเข้าและผลลัพธ์
* **Input (กรณีปกติ):** `pots&pans`
  * **Output (Recursive):** `snap&stop`
  * **Output (Iterative):** `snap&stop`
* **Input (กรณีพิเศษ - สตริงว่าง):** `""`
  * **Output:** `""` (ไม่เกิด Error)
* **Input (กรณีพิเศษ - null):** `null`
  * **Output:** `null` (ไม่เกิด Error)

### 5. การวิเคราะห์ Time Complexity
* **Recursive Algorithm:** $\mathcal{O}(n^2)$ เนื่องจากการใช้เครื่องหมาย `+` ต่อสตริงในภาษา Java จะสร้าง Object ใหม่ทุกครั้ง ซึ่งใช้เวลา $\mathcal{O}(n)$ ในแต่ละรอบของการเรียกซ้ำ $n$ ครั้ง (เมื่อ $n$ คือความยาวของสตริง)
* **Iterative Algorithm:** $\mathcal{O}(n)$ เนื่องจากลูปทำงาน $n$ รอบพอดี และการใช้คลาส `StringBuilder` มีประสิทธิภาพในการต่อสตริงโดยใช้เวลาเฉลี่ยเพียง $\mathcal{O}(1)$ ต่อรอบ

### 6. การวิเคราะห์ Space Complexity
* **Recursive Algorithm:** $\mathcal{O}(n)$ จากการใช้หน่วยความจำใน Call Stack ซ้อนกันลึก $n$ ชั้น (และอาจพุ่งสูงถึง $\mathcal{O}(n^2)$ ถ้ารวมถึงการจองหน่วยความจำจากการสร้าง String Object ใหม่ซ้ำๆ)
* **Iterative Algorithm:** $\mathcal{O}(n)$ ใช้พื้นที่เพิ่มเติมสำหรับ `StringBuilder` เพียง 1 ชุด ซึ่งมีขนาดแปรผันตามความยาวของสตริงต้นฉบับ โดยไม่มีการซ้อนทับของ Call Stack

### 7. การเปรียบเทียบข้อดีและข้อจำกัดของแต่ละอัลกอริทึม
* **Recursive Algorithm:** 
  * **ข้อดี:** โค้ดสั้น กระชับ อ่านเข้าใจง่ายในเชิงตรรกะคณิตศาสตร์
  * **ข้อจำกัด:** เปลืองหน่วยความจำ Stack อย่างมาก และจากการทดสอบจริงพบว่าเมื่อเจอสตริงขนาด 10,000 ตัวอักษร โปรแกรมจะเกิดข้อผิดพลาด `StackOverflowError` ทันที
* **Iterative Algorithm:**
  * **ข้อดี:** ทำงานรวดเร็ว ใช้หน่วยความจำน้อยกว่า และมีความเสถียรสูง จัดการข้อมูลขนาดหมื่นตัวอักษรได้อย่างราบรื่น
  * **ข้อจำกัด:** โค้ดมีความยาวมากกว่าเล็กน้อย และต้องพึ่งพาคลาสตัวช่วยอย่าง `StringBuilder` เพื่อรีดประสิทธิภาพสูงสุด

### 8. สรุปว่าอัลกอริทึมใดเหมาะสมกว่าภายใต้เงื่อนไขใด
**Iterative Algorithm มีความเหมาะสมมากกว่าอย่างชัดเจน** ภายใต้เงื่อนไขการทำงานจริงที่ต้องรองรับข้อมูลขนาดใหญ่ การใช้ลูปร่วมกับ `StringBuilder` จะการันตีได้ว่าโปรแกรมสามารถประมวลผลสำเร็จอย่างรวดเร็วโดยไม่หยุดทำงานผิดปกติ ในขณะที่วิธี Recursive จะเหมาะสมก็ต่อเมื่อใช้งานกับสตริงที่มีขนาดสั้นมากๆ และต้องการเน้นความกระชับของโค้ดเท่านั้น
