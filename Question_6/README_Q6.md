# ข้อ 6 การค้นหาคู่จำนวนที่มีผลรวมเท่ากับ k

### 1. คำอธิบายแนวคิดของอัลกอริทึมแต่ละวิธี
* **อัลกอริทึมที่ 1 (Brute Force):** ใช้ลูปซ้อนกัน 2 ชั้น (Nested Loops) เพื่อจับคู่สมาชิกทุกคู่ที่เป็นไปได้ในอาร์เรย์ แล้วตรวจสอบว่ามีคู่ใดที่บวกกันแล้วได้ผลรวมเท่ากับ $k$ หรือไม่
* **อัลกอริทึมที่ 2 (Recursive Two-Pointer):** กำหนดตัวชี้ `left = 0` และ `right = n - 1` คำนวณผลรวมของ `a[left] + a[right]` [cite: 2]
  * หากผลรวมเท่ากับ $k$ ถือว่าพบคำตอบและคืนค่า `true` [cite: 2]
  * หากผลรวมน้อยกว่า $k$ ให้เพิ่มค่า `left` (ขยับขวาเพื่อเพิ่มผลรวม) [cite: 2]
  * หากผลรวมมากกว่า $k$ ให้ลดค่า `right` (ขยับซ้ายเพื่อลดผลรวม) [cite: 2]
  * **Base Case (กรณีฐาน):** `if (left >= right)` หยุดการทำงานและคืนค่า `false` เมื่อตัวชี้วิ่งมาชนกันโดยไม่พบคำตอบ
  * **Recursive Case (กรณีเวียนเกิด):** เรียกเมธอดแบบเวียนเกิดกับช่วงใหม่ (`left` หรือ `right` ที่ถูกปรับเปลี่ยนแล้ว) [cite: 2]
* **อัลกอริทึมที่ 3 (Binary Search):** ใช้ลูปเพื่อเลือกสมาชิก `a[i]` ทีละตัว [cite: 2] จากนั้นนำค่าเป้าหมายที่ต้องการคือ `k - a[i]` ไปค้นหาในสมาชิกส่วนที่เหลือ (ตั้งแต่ `i + 1` จนจบ) โดยใช้เทคนิค Binary Search (เนื่องจากอาร์เรย์เรียงลำดับมาแล้ว) [cite: 2]

### 2. Pseudocode หรือผังขั้นตอนการทำงาน
**Algorithm 1: Brute Force**
```text
FUNCTION findPairBruteForce(a, k)
    FOR i = 0 TO LENGTH(a) - 1 DO
        FOR j = i + 1 TO LENGTH(a) - 1 DO
            IF a[i] + a[j] == k THEN
                RETURN true
            END IF
        END FOR
    END FOR
    RETURN false
END FUNCTION
```

**Algorithm 2: Recursive Two-Pointer**
```text
FUNCTION findPairRecursive(a, k, left, right)
    IF left >= right THEN RETURN false END IF
    
    sum = a[left] + a[right]
    IF sum == k THEN
        RETURN true
    ELSE IF sum < k THEN
        RETURN findPairRecursive(a, k, left + 1, right)
    ELSE
        RETURN findPairRecursive(a, k, left, right - 1)
    END IF
END FUNCTION
```

**Algorithm 3: Binary Search**
```text
FUNCTION findPairBinarySearch(a, k)
    FOR i = 0 TO LENGTH(a) - 1 DO
        target = k - a[i]
        IF BINARY_SEARCH(a, target, i + 1, LENGTH(a) - 1) IS FOUND THEN
            RETURN true
        END IF
    END FOR
    RETURN false
END FUNCTION
```

### 5. การวิเคราะห์ Time และ Space Complexity
| อัลกอริทึม | แนวคิด | Time Complexity | Space Complexity |
| :--- | :--- | :--- | :--- |
| **Brute Force** | ตรวจสอบทุกคู่ [cite: 3] | $\mathcal{O}(n^2)$ (ลูปซ้อนลูป) | $\mathcal{O}(1)$ |
| **Recursive Two-Pointer** | ลดขอบเขตการค้นหาทีละตำแหน่ง [cite: 3] | $\mathcal{O}(n)$ (เลื่อนตัวชี้เข้าหากัน 1 รอบ) | $\mathcal{O}(n)$ (Call Stack ลึกสูงสุด $n$ ชั้น) |
| **Binary Search** | ค้นหาค่าคู่สมของสมาชิกแต่ละตัว [cite: 3] | $\mathcal{O}(n \log n)$ (วนลูป $\mathcal{O}(n)$ ทำ Binary Search $\mathcal{O}(\log n)$) | $\mathcal{O}(1)$ |

### 6. การวิเคราะห์เหตุผลการใช้งาน Two-Pointer กับอาร์เรย์
* **เหตุใด Two-Pointer จึงใช้ได้เมื่ออาร์เรย์เรียงลำดับแล้ว?**
  * เพราะการเรียงลำดับทำให้เกิด "ทิศทางของค่า" ที่ชัดเจน [cite: 3] หากผลรวมของตัวซ้ายสุด (ค่าน้อย) และขวาสุด (ค่ามาก) ออกมา **"น้อยเกินไป"** เราย่อมรู้แน่ชัดว่าต้องขยับตัวซ้ายให้ใหญ่ขึ้น (ขยับขวา) เพื่อให้ผลรวมเพิ่มขึ้น หากผลรวม **"มากเกินไป"** ก็ขยับตัวขวาให้เล็กลง (ขยับซ้าย) อัลกอริทึมจึงสามารถตัดตัวเลือกที่ผิดทิ้งไปได้อย่างรวดเร็วและเป็นระบบ
* **จะเกิดอะไรขึ้นหากนำวิธีนี้ไปใช้กับอาร์เรย์ที่ยังไม่เรียงลำดับ?**
  * **โปรแกรมจะทำงานผิดพลาด (ได้ผลลัพธ์ที่ไม่ถูกต้อง)** [cite: 3] เพราะหากข้อมูลสะเปะสะปะ การที่ผลรวมออกมา "น้อยเกินไป" การเลื่อนตัวชี้ไปทางขวาอาจไปเจอเลขที่ "น้อยลงกว่าเดิม" ก็ได้ ทำให้ตรรกะการขยับซ้าย-ขวารวนไปหมด และอาจพลาดคู่คำตอบที่ถูกต้องไปอย่างง่ายดาย

### 7. การเปรียบเทียบข้อดีและข้อจำกัดของแต่ละอัลกอริทึม
* **Brute Force:** ใช้งานได้กับอาร์เรย์ทุกรูปแบบ (เรียงหรือไม่เรียงก็ได้) แต่มันทำงานช้าที่สุด $\mathcal{O}(n^2)$ ไม่เหมาะกับข้อมูลปริมาณมาก
* **Binary Search:** เร็วกว่า Brute Force แต่ก็ยังต้องเสียเวลาทำงานถึง $\mathcal{O}(n \log n)$ และต้องการข้อมูลที่เรียงลำดับแล้ว
* **Recursive Two-Pointer:** เป็นวิธีที่ทำงานเร็วที่สุด $\mathcal{O}(n)$ แลกมากับข้อจำกัดว่าข้อมูลต้องเรียงลำดับมาก่อนเท่านั้น และมีความเสี่ยงเรื่อง Space Complexity $\mathcal{O}(n)$ จากการใช้ Call Stack 

### 8. สรุปว่าอัลกอริทึมใดเหมาะสมกว่าภายใต้เงื่อนไขใด
* **Two-Pointer (แบบ Iterative) จะเป็นวิธีที่สมบูรณ์แบบที่สุด** สำหรับโจทย์ข้อนี้ เนื่องจากข้อมูลรับประกันว่า *เรียงลำดับจากน้อยไปมากแล้ว* (ตามโจทย์กำหนด) การใช้ Two-Pointer จะให้ประสิทธิภาพด้านเวลาดีที่สุดคือ $\mathcal{O}(n)$
* *(อย่างไรก็ตาม ในตัวเลือกตามโจทย์สั่งเป็นแบบ Recursive Two-Pointer จึงทำให้ต้องยอมรับข้อจำกัดเรื่องเปลือง Stack Memory ไปโดยปริยาย เมื่อเทียบกันตามตัวเลือก 3 ข้อนี้ Two-Pointer ก็ยังถือว่าเหมาะสมที่สุดในแง่ของความเร็ว)*
