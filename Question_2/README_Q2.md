# ข้อ 2 การตรวจสอบ Palindrome

### 1. คำอธิบายแนวคิดของอัลกอริทึม
* **Algorithm 1 (Reverse and Compare):** ทำการสร้างสตริงใหม่ที่เรียงลำดับตัวอักษรย้อนกลับจากสตริงต้นฉบับ จากนั้นนำสตริงทั้งสองมาเปรียบเทียบกัน หากเหมือนกันทุกประการแสดงว่าเป็น Palindrome
* **Algorithm 2 (Recursive Two-Pointer):** ใช้ตัวชี้ (Pointer) สองตัว คือ `left` ชี้ที่ตัวอักษรแรก และ `right` ชี้ที่ตัวอักษรสุดท้าย นำมาเปรียบเทียบกัน หากตรงกันให้ขยับตัวชี้เข้าหากัน (`left+1`, `right-1`) แล้วเรียกซ้ำ (Recursive) เพื่อตรวจสอบคู่ถัดไปจนกว่าตัวชี้จะชนกันตรงกลาง

### 2. Pseudocode
**Algorithm 1: Reverse and Compare**
```text
FUNCTION isPalindromeByReverse(s)
    cleaned_s = REMOVE NON-ALPHANUMERIC AND CONVERT TO LOWERCASE(s)
    reversed_s = REVERSE(cleaned_s)
    IF cleaned_s == reversed_s THEN
        RETURN true
    ELSE
        RETURN false
    END IF
END FUNCTION
```

**Algorithm 2: Recursive Two-Pointer**
```text
FUNCTION isPalindromeRecursive(s, left, right)
    IF left >= right THEN
        RETURN true
    END IF
    
    IF s[left] != s[right] THEN
        RETURN false
    END IF
    
    RETURN isPalindromeRecursive(s, left + 1, right - 1)
END FUNCTION
```

### 3. การอธิบาย Base Case และ Recursive Case (สำหรับ Algorithm 2)
* **Base Case (กรณีฐาน):** มี 2 กรณีเพื่อหยุดการทำงาน
  1. `if (left >= right)`: เมื่อตัวชี้ทั้งสองวิ่งมาชนกันหรือไขว้กันตรงกลาง แสดงว่าตรวจสอบครบทุกคู่แล้วและตรงกันทั้งหมด เมธอดจะคืนค่า `true` 
  2. `if (s.charAt(left) != s.charAt(right))`: เมื่อตรวจพบว่าตัวอักษรคู่ซ้าย-ขวาไม่ตรงกัน เมธอดจะคืนค่า `false` และหยุดการทำงานทันที (Early Exit)
* **Recursive Case (กรณีเวียนเกิด):** `return isPalindromeRecursive(s, left + 1, right - 1);` หากตัวอักษรคู่ปัจจุบันตรงกัน จะเรียกตัวเองซ้ำโดยขยับตัวชี้ `left` ไปขวา 1 ตำแหน่ง และขยับ `right` ไปซ้าย 1 ตำแหน่ง เพื่อตรวจสอบคู่ถัดไปด้านใน

### 4. งานวิเคราะห์และเปรียบเทียบอัลกอริทึม
จากการวิเคราะห์การทำงาน สามารถเปรียบเทียบตามประเด็นทั้ง 6 ข้อที่กำหนดได้ดังนี้:
* **กรณีที่สตริงเป็น Palindrome:** แบบ Reverse จะต้องทำการกลับด้านสตริงทั้งหมดและเปรียบเทียบทีละตัวอักษรจนจบ ส่วนแบบ Recursive จะต้องเปรียบเทียบและเรียกซ้ำลึกเข้าไปจนถึงกึ่งกลางของสตริง
* **กรณีที่ตัวอักษรคู่แรกไม่ตรงกัน:** แบบ Reverse ยังคงต้องทำงานเต็มรูปแบบโดยสร้างสตริงกลับด้านทั้งชุดก่อนจึงจะรู้ผล ในขณะที่แบบ Recursive จะตรวจพบความขัดแย้งและหยุดการทำงานได้ตั้งแต่รอบแรก
* **ความสามารถในการหยุดทำงานก่อน (Early Exit):** แบบ Reverse ไม่มีคุณสมบัตินี้ แต่แบบ Recursive มีคุณสมบัตินี้อย่างสมบูรณ์ ซึ่งช่วยประหยัดเวลาได้มากเมื่อพบจุดที่ไม่ตรงกัน
* **Best-case Time Complexity:** แบบ Reverse จะใช้เวลา $\mathcal{O}(n)$ เสมอเพราะต้องสลับด้านสตริงทั้งหมด แต่แบบ Recursive หากตัวอักษรคู่แรกไม่ตรงกันจะหยุดทำงานทันที ทำให้ใช้เวลาเพียง $\mathcal{O}(1)$ 
* **Worst-case Time Complexity:** ทั้ง 2 วิธีใช้เวลา $\mathcal{O}(n)$ เท่ากัน ซึ่งจะเกิดขึ้นเมื่อสตริงเป็น Palindrome และต้องตรวจสอบจนครบทุกคู่
* **Space Complexity:** แบบ Reverse จะใช้พื้นที่ $\mathcal{O}(n)$ สำหรับการเก็บสตริงตัวใหม่ ส่วนแบบ Recursive ใช้พื้นที่ $\mathcal{O}(n)$ เช่นกัน แต่เป็นหน่วยความจำใน Call Stack ตามความลึกของการเรียกซ้ำ

### 5. การจัดการเงื่อนไขเพิ่มเติมของโจทย์
เพื่อให้โปรแกรมทำงานได้ตามเงื่อนไข (ละเว้นตัวพิมพ์เล็ก-ใหญ่, ช่องว่าง, และเครื่องหมายวรรคตอน) ทั้ง 2 อัลกอริทึมจะถูกออกแบบให้มีการทำความสะอาดข้อมูล (Pre-processing) ก่อนเริ่มตรวจสอบ โดยแปลงอักษรทั้งหมดเป็นตัวพิมพ์เล็กและตัดอักขระพิเศษทิ้งไป

### 6. สรุปความเหมาะสม
**Recursive Two-Pointer มีความเหมาะสมมากกว่า** เนื่องจากมีประสิทธิภาพโดยรวมสูงกว่า การมีคุณสมบัติ Early Exit ทำให้เมื่อเจอข้อมูลที่ไม่ใช่ Palindrome โปรแกรมจะตัดจบและคืนค่าได้ทันที (ใช้เวลาเพียง $\mathcal{O}(1)$) แตกต่างจากวิธี Reverse ที่บังคับกินทรัพยากร $\mathcal{O}(n)$ เต็มจำนวนในทุกกรณีโดยไม่จำเป็น
