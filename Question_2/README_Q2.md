# ข้อ 2 การตรวจสอบ Palindrome

### 1. คำอธิบายแนวคิดของอัลกอริทึม
* **Algorithm 1 (Reverse and Compare):** ทำการสร้างสตริงใหม่ที่เรียงลำดับตัวอักษรย้อนกลับจากสตริงต้นฉบับ จากนั้นนำสตริงทั้งสองมาเปรียบเทียบกัน หากเหมือนกันทุกประการแสดงว่าเป็น Palindrome
* **Algorithm 2 (Recursive Two-Pointer):** ใช้ตัวชี้ (Pointer) สองตัว คือ `left` ชี้ที่ตัวอักษรแรก และ `right` ชี้ที่ตัวอักษรสุดท้าย นำมาเปรียบเทียบกัน หากตรงกันให้ขยับตัวชี้เข้าหากัน (`left+1`, `right-1`) แล้วเรียกซ้ำ (Recursive) เพื่อตรวจสอบคู่ถัดไปจนกว่าตัวชี้จะชนกันตรงกลาง

*(หมายเหตุ: ทั้ง 2 อัลกอริทึมมีการจัดการสตริงก่อนประมวลผล โดยการตัดช่องว่าง เครื่องหมายวรรคตอน และแปลงเป็นตัวพิมพ์เล็กทั้งหมด เพื่อให้ตรงตามเงื่อนไขเพิ่มเติมของโจทย์)*

### 2. Pseudocode
**Algorithm 1: Reverse and Compare**
```text
FUNCTION isPalindromeByReverse(s)
    cleaned_s = REMOVE NON-ALPHANUMERIC AND CONVERT TO LOWERCASE(s)
    reversed_s = REVERSE(cleaned_s)
    IF cleaned_s == reversed_s THEN
        RETURN true
    ELSE
        RETURN false
    END IF
END FUNCTION
```

**Algorithm 2: Recursive Two-Pointer**
```text
FUNCTION isPalindromeRecursive(s, left, right)
    IF left >= right THEN
        RETURN true
    END IF
    
    IF s[left] != s[right] THEN
        RETURN false
    END IF
    
    RETURN isPalindromeRecursive(s, left + 1, right - 1)
END FUNCTION
```

### 3. งานวิเคราะห์และเปรียบเทียบ (Analysis)

จากการวิเคราะห์การทำงาน จะเห็นความแตกต่างของทั้ง 2 อัลกอริทึมได้อย่างชัดเจนครับ สำหรับวิธีแรก (Reverse and Compare) ตัวโปรแกรมจะต้องทำงานแบบเต็มรูปแบบเสมอ คือต้องสร้างสตริงที่กลับด้านขึ้นมาใหม่ทั้งชุดแล้วค่อยนำมาเปรียบเทียบทีละตัวอักษร ไม่ว่าสตริงนั้นจะเป็น Palindrome หรือไม่ก็ตาม (ต่อให้ตัวอักษรคู่แรกไม่ตรงกัน ก็ต้องกลับด้านให้เสร็จก่อนอยู่ดี) ทำให้วิธีนี้ไม่มีความสามารถในการหยุดทำงานก่อนกำหนด (Early Exit) ส่งผลให้ Time Complexity ทั้งในกรณีที่ดีที่สุด (Best-case) และแย่ที่สุด (Worst-case) อยู่ที่ $\mathcal{O}(n)$ คงที่เสมอ นอกจากนี้ยังต้องเปลืองพื้นที่หน่วยความจำเพื่อเก็บสตริงตัวใหม่อีกด้วย ทำให้ Space Complexity อยู่ที่ $\mathcal{O}(n)$ในทางกลับกัน วิธีที่สอง (Recursive Two-Pointer) ทำงานได้ยืดหยุ่นกว่ามากครับ หากสตริงนั้นเป็น Palindrome โปรแกรมจะเปรียบเทียบตัวอักษรและเรียกซ้ำลึกเข้าไปจนถึงตรงกลางสตริง ซึ่งจะใช้เวลาทำงานสูงสุดที่ $\mathcal{O}(n)$ (Worst-case) และกินพื้นที่ Space Complexity ที่ $\mathcal{O}(n)$ ตามความลึกของการเรียก Call Stack แต่จุดเด่นที่สำคัญคือวิธีนี้มี Early Exit ครับ ถ้าหากตรวจพบว่าตัวอักษรคู่แรกสุดไม่ตรงกัน โปรแกรมจะหยุดทำงานและคืนค่า false ทันทีโดยไม่ต้องประมวลผลต่อ ทำให้ในกรณีที่ดีที่สุด (Best-case) โปรแกรมจะใช้เวลาทำงานเพียงแค่ $\mathcal{O}(1)$ เท่านั้น

### 4. สรุป
โดยรวมแล้ววิธี Recursive Two-Pointer ถือว่ามีประสิทธิภาพที่ดีกว่าครับ สาเหตุหลักมาจากคุณสมบัติ Early Exit ที่ช่วยตัดจบการทำงานได้อย่างรวดเร็วในกรณีที่ข้อมูลไม่ได้เป็น Palindrome ในขณะที่วิธี Reverse and Compare จะบังคับกินทรัพยากรทั้งเวลาและหน่วยความจำเพื่อสร้างสตริงใหม่ทั้งชุดเสมอ โดยไม่สนใจเลยว่าข้อมูลนำเข้าจะมีหน้าตาเป็นอย่างไร
